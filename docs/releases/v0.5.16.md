# v0.5.16 - goneat v0.6.9, Go 1.26.11, npm 12.2.2

**Date:** 2026-11-20

**Type:** Patch (tool pins, CVE fixes)

## Summary

Rebuilds `goneat-tools-slim-musl`, `goneat-tools-runner-musl`, and `goneat-tools-runner-glibc` with goneat **v0.6.9** and npm **12.2.2**. npm 12.2.2 bundles undici 6.29.1, so the undici overlay is removed. Go moves to **1.26.11**, syft to **v1.57.1**, grype to **v0.121.3** and trivy to **v0.76.2**. The musl goneat images pin OpenSSL **3.5.9-r1** and zlib **1.4-r0** (CVE-2026-85091), the musl sbom-tools images pin jq **1.8.2-r0**, and the glibc images ship yq **v4.54.3** with a per-architecture SHA256 check. The CVE-2026-34040, CVE-2026-39822 and CVE-2026-56852 entries are removed from `.trivyignore`, and the residual-findings document is closed. Node **22.23.4**, golangci-lint **2.14.0**, shellsentry **v0.1.7**, sfetch **v0.4.15**, and uv **0.13.4** are unchanged.

## Changes

1. `goneat` `v0.6.8` → `v0.6.9` in the slim image and both full runners. Dockerfile ARGs, `manifests/tools.json`, the Makefile bootstrap minimum, the image README, and built-image `goneat version` checks move together. goneat v0.6.9 is inside the 7-day cooling window. The exception runs until 2026-11-27T14:34:44Z. See `docs/operations/2026-11-20-cooling-exception.md`.
2. `npm` `12.2.1` → `12.2.2` in the slim image and both full runners, installed only after its sha512 integrity matches the committed `NPM_INTEGRITY`. npm 12.2.2 bundles undici 6.29.1, so the undici overlay step, the `UNDICI_*` ARGs, the `undici` manifest entry, its `validate-pins` checks, and the overlay section of `RELEASE_CHECKLIST.md` are removed.
3. Go `1.26.10` → `1.26.11`: the Go toolchain in both full runners (SHA256-pinned per architecture) and the `golang` builder images for the goneat-tools and sbom-tools images. Built-image checks assert `go1.26.11`.
4. `syft` `v1.56.0` → `v1.57.1` and `grype` `v0.121.1` → `v0.121.3` on both full runners and all three sbom-tools images, and `trivy` `v0.76.1` → `v0.76.2` on the sbom-tools images. Release tarballs are verified against pinned per-architecture SHA256 values. syft and grype use golang.org/x/net v0.62.0, and grype v0.121.3 no longer vendors docker/docker, so the `CVE-2026-34040` entry is removed from `.trivyignore`. Built-image checks assert the trivy version, and `.goneat/tools.yaml` requires trivy 0.76.2.
5. Alpine 3.24 `git` `2.54.0-r0` → `2.54.1-r0` in `goneat-tools-runner-musl`.
6. OS security pins in `goneat-tools-slim-musl` and `goneat-tools-runner-musl`: `libcrypto3` and `libssl3` `3.5.9-r0` → `3.5.9-r1`, and `zlib` `1.4-r0` (CVE-2026-85091; the pinned node alpine digest ships 1.3.2-r0). Alpine replaced the OpenSSL 3.5.9-r0 build with 3.5.9-r1 and no longer serves 3.5.9-r0. OpenSSL 3.5.9-r1 is inside the cooling window; the exception runs until 2026-11-25T23:31Z.
7. Alpine 3.21 `jq` `1.7.1-r0` → `1.8.2-r0` in `sbom-tools-slim-musl` and `sbom-tools-runner-musl`. Alpine 3.21 no longer serves 1.7.1-r0. jq 1.8.2-r0 is inside the cooling window; the exception runs until 2026-11-22T23:21Z.
8. `yq` `v4.53.3` → `v4.54.3` in `goneat-tools-runner-glibc` and `sbom-tools-runner-glibc`. The release binary was previously downloaded without verification; it is now checked against pinned per-architecture SHA256 values. The `CVE-2026-39822` and `CVE-2026-56852` entries are removed from `.trivyignore`, which now has no entries.
9. `docs/operations/2026-11-02-residual-findings-exception.md` is closed. A 2026-11-20 `trivy image` scan with no `.trivyignore` of the six goneat-tools and sbom-tools images found no fixable HIGH/CRITICAL findings. The remaining findings are Debian base-image packages with no fixed version.

## Upgrade notes

Consumers pinned to `:v0.5.15` (or its digest) should retag to `:v0.5.16` after GA. Verify an image with `cosign verify --certificate-identity https://github.com/fulmenhq/fulmen-toolbox/.github/workflows/release.yml@refs/tags/v0.5.16 --certificate-oidc-issuer https://token.actions.githubusercontent.com <image>@<digest>`, for the index digest or the platform digest you run. Checksum manifests verify with the keys from the repository at the tag; see `docs/security/release-signing.md`.
