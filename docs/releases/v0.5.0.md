# Release Notes — v0.5.0

## v0.5.0 (2026-06-XX)

**Runner content delta + full fixable-CVE sweep — `zip`, `CGO_ENABLED` docs, deterministic OS-security pins, Go 1.26.4, scanner/tool currency**

The first image-content rebuild since v0.4.x. It started as a downstream-driven patch (add `zip`, document `CGO_ENABLED`) and — because any image touch forces a full rebuild and a downstream adoption cascade — was deliberately widened to sweep **every fixable HIGH/CRITICAL CVE** on the published runners. After the sweep, all four runner images report **0 fixable HIGH/CRITICAL findings** (trivy, `--ignore-unfixed`, with documented `.trivyignore` exceptions).

Versioned **minor** (not patch): `zip` is a new tool consumers can rely on, and the v0.4.2 brief reserved v0.5.0 for the next runner content delta.

### Background

Two asks arrived in `#repo-fulmen-toolbox-ops` from agent-lima-devlead, field-validated against `goneat-tools-runner-glibc:v0.4.2` via the `forge-microtool-gimlet` CI catch-up: (1) the runners ship `python3` and `unzip` but not `zip`, so release packaging building a Windows `.zip` failed; (2) the `CGO_ENABLED=1` preset breaks cross-compilation and is a Makefile `?=` override trap. A triage of the rebuilt image showed a base-digest refresh alone could not close the OS CVEs (Debian bases lag the security repo), and that the remaining fixable surface was small and bounded — so the full sweep was bundled into one cut, to be validated via a prerelease RC before GA.

### Changes

#### B — downstream asks

- **`zip` CLI** added to `goneat-tools-runner-{glibc,musl}` (beside the existing `unzip`).
- **`CGO_ENABLED=1` documented.** The runners intentionally preset `CGO_ENABLED=1` (CGO-capable). This overrides Go's per-target default of `0`, so a plain `go build` for a non-native `GOOS`/`GOARCH` fails (`gcc: error: unrecognized command-line option '-m64'`), and a Makefile `CGO_ENABLED ?= 0` is silently overridden by the image env. Consumers building static or cross binaries should set `CGO_ENABLED=0` explicitly (`:=`/`override`, not `?=`). Documented in `docs/user-guide/container-usage-patterns.md` and `docs/images/goneat-tools.md`. Whether to drop the preset is tracked in #14.

#### A — deterministic OS-security-pin model

- **`libgnutls30` pinned to `3.7.9-2+deb12u7`** on both glibc runners, closing CRITICAL `CVE-2026-33845` / `CVE-2026-42010` and HIGH `CVE-2026-33846` / `CVE-2026-3833` / `CVE-2026-42009`. The `bookworm-slim` base ships `deb12u6`; the security repo carries `deb12u7`. A base-digest refresh cannot close this — the explicit apt pin forces the patched build.
- **New `make validate-apt-pins`** (`scripts/validate-apt-pins.sh`) — the apt analog of `validate-apk-pins`: verifies apt security pins are available in the Debian repos (incl. bookworm-security) and warns when a newer candidate exists. Wired into `make quality`. `validate-pins` extended to enforce the pin's presence in the Dockerfiles. `manifests/tools.json` gains its first `source: "apt"` entry (schema enum extended).

#### C — fixable-lang sweep (toolchain + tool currency)

- **Go `1.26.2 → 1.26.4`** (`GO_VERSION` + tarball checksums + the coupled `GO_IMAGE` builder digest, kept in sync) on both goneat runners. Rebuilds the in-house Go tools and ships the patched `/opt/go`, clearing the Go-stdlib CVE class in those binaries.
- **`goneat v0.5.9 → v0.5.13`** — picks up patched `go-git`/`go-billy`/OpenTelemetry deps (clears `CVE-2026-44973`, `CVE-2026-45022`, `CVE-2026-29181`, `CVE-2026-39883`). v0.5.13 is a drop-in over v0.5.12 (YAML check/apply fidelity, markdown-lint additions; same CVE-relevant deps).
- **`syft v1.41.1 → v1.45.0`, `grype v0.107.1 → v0.113.0`, `trivy v0.69.3 → v0.71.0`** (sbom-tools), **`yq v4.49.2 → v4.53.2`** (glibc fetched binary) — clear vendored-dependency CVEs (grpc, docker/cli, containerd, go-git, OpenTelemetry) and their stdlib. musl `yq-go` stays at the alpine-packaged version (no newer build in the alpine 3.21/3.23 repos).
- **Final-stage base image digests refreshed** so runtime bases rebuild on patched OS package sets (`node:22-alpine`, `node:22-bookworm-slim`, `alpine:3.21`, `debian:bookworm-slim`). All version/digest changes are lockstep across the Dockerfiles and `manifests/tools.json`.

### Updated Images

All six tool images are rebuilt. `valkey-server-glibc` is unchanged (its base was already current). No consumer-facing interface change beyond the new `zip` binary and patched package/tool versions.

### CVE posture

Every **actionable** HIGH/CRITICAL on the published runners is fixed; all four runners scan to **0 fixable findings**. Two residual categories remain (neither a regression):

1. **No-fix, gate-excluded** by `ignore-unfixed: true` — dominated by `linux-libc-dev` (kernel-header package, not applicable in-container) plus Debian won't-fix (`zlib1g` CVE-2023-45853, `libsqlite3`) and unfixed-upstream `python3.11`/`perl`.
2. **Fixed in a dependency, but no upstream release of the prebuilt tool ships the fix yet** — `yq`'s embedded Go stdlib (8), one `grype` vendored dependency, and `picomatch` inside the node base's bundled npm. We ship the latest upstream version of each. These are tracked with time-boxed, rationale-bearing `.trivyignore` entries (review by 2026-09-05) and will be dropped as upstream rebuilds land — not by re-architecting our delivery to build these tools from source.
