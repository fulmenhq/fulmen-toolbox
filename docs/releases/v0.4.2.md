# Release Notes — v0.4.2

## v0.4.2 (2026-05-18)

**Release-Pipeline Hygiene — Native arm64 Runners + Forced apk Pin Refresh**

CI plumbing release. No new tools, no Dockerfile architecture changes, no API or interface delta for consumers — but the release pipeline itself was rebuilt. Per-arch builds now run on native runners instead of QEMU-emulated amd64, eliminating the qemu-user aarch64 SIGILL roulette that left v0.4.1 partially published. Two tightly-scoped apk pin bumps were also forced by alpine 3.23 upstream rotation between v0.4.1 and now.

### Background

v0.4.1 (2026-05-05) tagged successfully but built only 6 of 7 image variants — `goneat-tools-runner-musl` crashed with `exit code: 132` (SIGILL) on Stage 5 final RUN of `images/goneat-tools/Dockerfile` during qemu-user aarch64 emulation. Two re-runs reproduced identically. Diagnosis (see `.plans/active/v0.4.1/brief.md` and `.plans/active/v0.4.2/brief.md`): Azure VM physical-host placement lottery — some host CPUs interact poorly with qemu-user aarch64 emulation, and re-runs could not reliably escape. A cleanroom Linux box with identical Docker + buildx + binfmt versions completed the same build in 57s, confirming the issue was host-specific to GitHub-hosted runners under emulation.

The fix is to stop emulating. Per-arch builds on native runners eliminate qemu-user from the critical path entirely.

### Changes

#### D1 — Native per-arch release matrix

`.github/workflows/release.yml` rewrite. Previously a single `release` job with a 7-row matrix on `ubuntu-latest-m`, building both platforms via `docker/build-push-action@v6` under QEMU. Now three jobs:

1. **`build`** — 14 cells (7 images × 2 arches). `runs-on: ${{ matrix.platform.runner }}` resolves to `ubuntu-latest-m` for amd64 and `ubuntu-latest-arm64-s` for arm64 (the org-standard native aarch64 runner across every 3 Leaps galaxy org). Single-platform build via `outputs: type=image,name=<repo>,push-by-digest=true,name-canonical=true,push=true`. Per-arch digest exported to a file (named after the SHA) and uploaded as a workflow artifact (`retention-days: 1`).
2. **`manifest`** — 7 cells. Downloads both per-arch digest artifacts for each image, then runs `docker buildx imagetools create` with one `-t` flag per canonical and alias tag to compose a multi-arch manifest in a single call. Resolves the composed manifest digest via `docker buildx imagetools inspect --format '{{json .Manifest}}' | jq -r '.digest'` for downstream use. Generates SBOM (via `anchore/sbom-action@v0`) and SHA256SUMS against the composed digest, and uploads to the GitHub release.
3. **`cosign`** — 7 cells. Unchanged shape; only the `needs:` dependency changed from `release` to `manifest`.

#### D2 — Pre-release tag guard

New conditional in the `Compute tags` step of the manifest job. When `$VERSION` contains `-` (e.g. `v0.4.2-rc.1`), only the exact `:v$VERSION` tag is published; `:latest` and `:v<major>` floats are skipped. The GitHub release is also marked `prerelease: true` and `make_latest: false` via explicit inputs to `softprops/action-gh-release@v2`. This removes a pre-existing foot-gun where any future pre-release tag would have moved consumer-visible floating tags.

Validated end-to-end on `v0.4.2-rc.1` (since deleted): workflow logs show only `:v0.4.2-rc.1` tag references — zero `:latest` or `:v0` emissions.

#### D3 — Forced apk pin refresh

The rc.1 dry-run surfaced two stale apk pins in `images/goneat-tools/Dockerfile` (the only Dockerfile built on the rolling `node:22-alpine` base). `make validate-apk-pins` confirmed both:

- `curl=8.17.0-r1` → `8.19.0-r0`
- `yq-go=4.49.2-r5` → `4.49.2-r6`

Both bumps mirrored in `manifests/tools.json`. `make validate-pins` (npm/GH-release sources) was clean. No other Dockerfile is affected (alpine:3.21-based images use independent older pins still present upstream; the `*-glibc` variants reference yq via GitHub release tag, not apk).

The drift was real and would have blocked any release attempted today regardless of the workflow change. The brief's original "no Dockerfile / no pin change" constraint was therefore expanded to include this minimal refresh.

#### D4 — v0.4.1 GitHub Release page deleted

To avoid showing a partial release in the repo's release list. The v0.4.1 git tag remains in history for traceability. Consumers should resolve to `:v0.4.2` (or `:v0` / `:latest`) for the full image set.

### Breaking Changes

None.

### Operational Notes

- arm64 release wall-clock is dramatically shorter under native runners. Reference data points from the rc.1 dry-run:
  - `goneat-tools-runner-glibc` arm64: ~12 min native (was ~1h+ under QEMU on v0.4.0)
  - `sbom-tools-runner-musl` arm64: ~2 min native
  - `valkey-server-glibc` arm64: ~2 min native
- Per-arch jobs run in parallel within each image's matrix row, so net release wall-clock is substantially reduced even though the total job count grew (7 → 14 build cells + 7 manifest cells).
- The `tonistiigi/binfmt` + qemu-user-static dependency surface is removed from the release-build critical path. The `cve-scan.yml` workflow's runtime exposure is unchanged; only build-time emulation is retired.
