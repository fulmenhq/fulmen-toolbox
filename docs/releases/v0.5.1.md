# v0.5.1 — Release-pipeline hygiene (manifest concurrency)

**Date:** 2026-07-31  
**Type:** Patch (workflow only; image contents identical to v0.5.0)

## Summary

Hardens `.github/workflows/release.yml` against GHCR write throttling during multi-arch manifest composition and alias tag copy. No consumer-facing image content change.

## Motivation

During `v0.5.0-rc.1` and `v0.5.0` GA:

- All per-arch **build** jobs succeeded.
- The **manifest** job matrix (7 images) ran fully concurrent (`fail-fast: false`, no `max-parallel`).
- Several cells failed on `docker buildx imagetools create` with **HTTP 429 Too Many Requests** while copying blobs / publishing alias tags (`:latest`, `:v0`, short names).
- Re-running **only the failed cells** always succeeded — pure throttle, not content or auth defects.

Evidence (v0.5.0 GA): 3 of 7 manifests failed under concurrency; recovery was `gh run rerun --failed`.

## Changes

1. **`max-parallel: 2`** on the `manifest` job strategy. Caps concurrent GHCR write pressure while keeping wall-clock acceptable (serial would be slow; 7-way is too hot).
2. **429/5xx-only retry/backoff** around `docker buildx imagetools create` — 5 attempts, exponential sleep starting at 15s, full jitter so matrix cells desync. Auth, 403, missing digests, and other permanent errors fail on the first attempt (no backoff burn).

Neither control alone is the whole fix: concurrency reduction lowers probability; scoped retry covers residual throttle without a full job re-run or masking real failures.

## Non-goals (this cut)

- Build-job matrix concurrency (builds were not the failure mode).
- Cosign matrix concurrency (downstream of successful manifests).
- BuildKit secrets / authenticated in-build GitHub fetches.
- LICENSE fetch `--retry` on local image builds.
- Image pin / CVE / tool content changes.

## Upgrade notes

Consumers tracking `:v0.5.0` or floating `:v0` / `:latest` see no functional image delta. Pipelines that pin digests from v0.5.0 need not move unless they want the new tag for hygiene.
